# W-24351415

## Context

Cut `forcedotcom/salesforcedx-templates` npm publish over to trusted publishing for `@salesforce/templates`.

The `npm` job in `.github/workflows/onRelease.yml` calls `salesforcecli/github-workflows/.github/workflows/npmPublish.yml@main`. It forwards repository secrets with `secrets: inherit`, which passes `NPM_TOKEN`.

Switch that job to OIDC trusted publishing, same shape as [salesforcecli/plugin-apex#972](https://github.com/salesforcecli/plugin-apex/pull/972): `permissions` for the id token, `trustedPublishing: true`, and do not pass `NPM_TOKEN`.

Publisher setup for `@salesforce/templates` against `onRelease.yml` is the stated blocker (item 1). This change is the workflow cutover only.

## Phases

### 1. Use npm trusted publishing on release

Commit: `ci: use npm trusted publishing on release`

Edit the `npm` job in `.github/workflows/onRelease.yml` to:

```yaml
  npm:
    permissions:
      id-token: write
      contents: read
    uses: salesforcecli/github-workflows/.github/workflows/npmPublish.yml@main
    needs: [getDistTag]
    with:
      trustedPublishing: true
      tag: ${{ needs.getDistTag.outputs.tag || 'latest' }}
      githubTag: ${{ github.event.release.tag_name || inputs.tag }}
```

Remove `secrets: inherit`. Leave `getDistTag` unchanged.

## Verification

- `npm` has `permissions.id-token: write` and `permissions.contents: read`.
- `with.trustedPublishing` is `true`.
- The job has no `secrets` block and no `NPM_TOKEN` mapping.
- `getDistTag`, `tag`, and `githubTag` are unchanged.
